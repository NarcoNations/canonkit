How it works

Metadata in. Trust decisions out.

CanonKit stays deliberately boring at its core: files, schema validation, a relationship graph, and predictable command-line output.

Step 01 · Mark

Add compact governance metadata

Keep the document readable. Add only the facts needed to establish identity, authority, lifecycle, ownership, visibility, lineage, and review expectations.

---
id: auth-architecture
title: Authentication Architecture
status: active
authority: canonical
owner: platform
version: 2.1
visibility: public
supersedes: [auth-architecture@1]
review_after: 2026-11-01
---
Step 02 · Check

Validate structure and relationships

The CLI checks required fields, allowed values, duplicate active authorities, broken references, supersession cycles, missing owners, overdue reviews, and unsafe visibility combinations.

canonkit validatecanonkit lintcanonkit graph
Step 03 · Resolve

Ask for the governing source

A deterministic resolver ranks eligible documents by scope, lifecycle, authority, specificity, and recency—while preserving provenance and explaining why a source won.

canonkit resolve "authentication"--scope app--explain
Step 04 · Share

Generate bounded context for tools

Export a safe agent pack containing only eligible sources and compact provenance. Internal or archived material requires explicit opt-in; unverified material never becomes pack authority.

canonkit pack--audience public--format json

Architecture

Small core. Explicit edges.

The v0.1 architecture is intentionally offline-capable and dependency-light. Git remains the audit trail; CanonKit supplies semantics and checks.

InputMarkdown + YAML

Existing repository files with compact frontmatter.

CoreParser + schema

Normalises metadata and rejects invalid states.

CorePolicy engine

Applies lifecycle, visibility, ownership, and review rules.

CoreTrust graph

Resolves lineage, conflicts, and supersession.

OutputCLI + JSON

Human reports, CI status, graphs, and agent packs.

Local filesystem only by default · network disabled · no model dependency · adapters are optional and isolated
Security model

Trust metadata without creating a new trust problem.

CanonKit handles sensitive repository knowledge, so v0.1 should minimise capability, fail closed, and make every inclusion explainable.

01

Offline by default

No telemetry, uploads, remote calls, or model execution in the core.

Mitigates accidental disclosure.
02

Read-only core

Validation and resolution never rewrite documents unless a separate explicit fix command is used.

Mitigates silent mutation.
03

Visibility gates

Private and restricted sources are excluded from packs unless policy and caller scope both allow them.

Mitigates context leakage.
04

Untrusted content

Document bodies are data, never executable instructions. Paths stay repository-bounded.

Mitigates prompt and path injection.
05

Explainable ranking

Every selected source includes its governing rule and rejected alternatives.

Mitigates false authority.
06

Human promotion

CanonKit detects conflicts and proposes changes; it never promotes a document to canonical automatically.

Mitigates governance capture.
