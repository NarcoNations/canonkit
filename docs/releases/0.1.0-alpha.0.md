# CanonKit 0.1.0-alpha.0 — draft release notes

**Status:** unreleased candidate. This document is not publication approval.

CanonKit is an open-source canonical knowledge governance toolkit from VibeLabz. It helps people and AI agents determine which repository documents are current, authoritative, owned, superseded, and safe to use.

## Included in the alpha candidate

- `canonkit validate` for schema, document-policy, and relationship diagnostics
- `canonkit list` and `canonkit graph` for bounded, body-free inspection
- `canonkit resolve` for deterministic governing-source selection and explanation
- `canonkit pack` for bounded, provenance-backed Markdown or JSON context packs
- public metadata schemas `1.0` and `1.1`
- local-first, read-only, network-disabled runtime behaviour
- public-only defaults and explicit wider-disclosure controls
- aggregate repository, document, content, and rendered-output budgets

## Package

- Candidate: `@vibelabz/canonkit@0.1.0-alpha.0`
- Binary: `canonkit`
- Runtime: Node.js 22 or newer
- Licence: MIT
- Runtime dependencies: `ajv` and `yaml`
- Locked distributable contents: 78 files under `dist/` and `schema/`, plus `README.md`, `LICENSE`, and package metadata

The package is still `private: true`, is absent from the public registry, and cannot yet be installed from npm. The future installation command remains unavailable until Stage 5.4 is explicitly approved.

## Security boundary

- Git access controls and review policy—not metadata alone—authenticate who may declare authority.
- Markdown bodies are untrusted evidence and must not independently authorise agent actions.
- Wider-audience packs can disclose repository content through standard output; operators control the destination.
- No hosted service, account system, telemetry, model call, or remote runtime is included.
- Npm organisation ownership, trusted publishing, provenance, and the first-publication bootstrap remain release blockers.

## Rehearsal boundary

The Stage 5.3 workflow builds, audits, packs, inspects, installs, imports, and exercises the private candidate on Ubuntu and macOS with Node.js 22 and 24. It has read-only repository permission, uses no npm credentials or secrets, receives no OIDC write permission, uploads no tarball, creates no tag or release, and contains no publication command.

## Known limitations

- Alpha stability: public contracts are versioned, but breaking changes may occur before `1.0.0`.
- Windows is not currently an asserted release target.
- Schema `1.0` remains valid but lacks the explicit subject model introduced in `1.1`.
- CanonKit validates declared governance; it cannot prove that human claims are truthful or properly authorised.
- It is not a prompt-injection sandbox for downstream AI systems.
